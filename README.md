# SpamShield — SMS Spam Detection & ML Algorithm Comparison

A small, reproducible university Machine Learning midterm project that classifies SMS
messages as **spam** or **ham (legitimate)** using **six** different algorithms, compares
their performance, and serves the result through an interactive Streamlit dashboard.

> This README is filled in progressively as the project is implemented. The final version
> documents setup, training, evaluation, the Lab 1–8 coverage table and known limitations.

## Objective

Train, evaluate and compare six classic machine learning algorithms on the same SMS
dataset and provide a working interface for classifying new messages.

## Performance comparison

All six models share the same cleaned dataset, the same stratified 80/20 split
(4,136 train / 1,035 test messages) and the same TF-IDF representation, so the numbers
below are directly comparable. Results are generated by running the pipeline, not
hand-written — regenerate them with `uv run python -m spamshield.train`.

| Decision Tree           | 0.9778   | 0.9426   | 0.8779   | 0.9091    | 0.8785       | 9.73      | 0.0185             | 11.98                |

`P`, `R` and `F1` are computed for the **spam** class, which is the minority class
(131 of the 1,035 test messages) and therefore the class that matters.

### Selecting a model

The model is selected using **training-only cross-validated spam F1**, as required for a
fair evaluation; the test set is reported afterwards for all six models and never used to
pick the winner. That selects the **Support Vector Machine** (CV F1 0.9553).

On the held-out test set Multinomial Naive Bayes actually scores *slightly* higher
(F1 0.9486 vs 0.9350). The two are within the noise of a 131-spam-message test set, and
this gap is a good illustration of why repeatedly optimising against test results
overfits the test set.

### Trade-offs

- **Naive Bayes** is the cheapest strong option: fastest to train, smallest memory, and
  the best test-set F1 here. Its independence assumption is clearly wrong for language,
  yet it works extremely well on sparse word counts.
- **Support Vector Machine** is very precise (no false positives on the test set) and the
  most consistent under cross-validation, but its recall is lower — it misses ~12% of
  spam. It also cannot produce probabilities, so the app shows a decision score instead.
- **Neural Network (MLP)** is the slowest to train and needs the most memory, for accuracy
  comparable to the linear models. A single hidden layer is enough here, but the extra
  cost buys little on 4,000 sparse features.
- **Logistic Regression** is fast, interpretable and reliable; its weakness is recall
  (0.8473), i.e. it lets more spam through than the other strong models.
- **Decision Tree** is the easiest to explain (if/else rules) but the weakest performer
  and the most prone to overfitting, which the depth tuning only partly controls.
- **K-Nearest Neighbors** is the slowest at inference and the most memory-hungry, because
  it stores the whole training set and compares against it at prediction time. It also has
  the worst recall.

Because accuracy is misleading on an imbalanced dataset (a model that never predicts spam
would still score ~87%), spam-class **F1, precision and recall** are the metrics that
drive every conclusion above.

Peak memory is measured with `tracemalloc`, which traces Python-level allocations only.
It does not include memory held by native numerical libraries and is **not** total process
memory.

## Technology stack

- **Python 3.12** (pinned via `.python-version`)
- **uv** for Python version selection, virtual environments and locked dependencies
- **pandas / NumPy** for data handling
- **scikit-learn** for ML and TF-IDF feature extraction
- **Matplotlib / Seaborn** for visualisations
- **Streamlit** for the frontend
- **joblib** for model serialization
- **pytest** for automated tests, **Ruff** for linting/formatting

## Getting started

```bash
# 1. Install the pinned Python and the locked dependencies
uv sync --locked
```
